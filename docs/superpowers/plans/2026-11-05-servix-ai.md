# Servix AI Implementation Plan

**Goal:** Add the customer Servix AI assistant and budget guide using the live API, with no mocked production data.

**Architecture:** A Retrofit service handles usage, pricing and feedback; a cancellable OkHttp stream shares the existing authenticated client and parses server-sent events. A session-scoped ViewModel owns in-memory chat state and Compose renders it with clear loading, privacy and error states.

**Constraints:** Customer functionality only; no secrets or telemetry; preserve existing client headers and refresh behavior; never run the production-writing verification tests. Backend route references: `reference/api-routes/ai.ts:67-113,147-152,185-190` and `reference/api-routes/aiFeedback.ts:25-31,43-78`.

## Steps
1. Bind the documented request/response fields and implement cancellable SSE, terminal errors, cut-off detection, and 404/non-stream fallback. Test parser and payload privacy offline.
2. Implement assistant, cancel, copy, feedback consent, quota/plan errors, usage meter, and real category-driven budget guidance. Reset all account-scoped state on sign-out or user change.
3. Add AI navigation and replace the dashboard placeholder. Keep guests browsing but require sign-in for AI requests.
4. Run focused offline tests and build through branch Actions, bump version on the test build, confirm APK release, and report device/live-API checks as unverified.
